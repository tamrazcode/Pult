# M11 — ACP Sign-in Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Finish the sign-in path for providers that report Needs sign-in: agent-managed methods run the ACP `authenticate` cycle and re-probe `session/new`; terminal methods get an honest copyable command plus Re-check, never sent to `authenticate`.

**Architecture:** Add `AcpConn::authenticate` and strict `-32000` detection, `AgentRuntime::authenticate` following the preflight spawn/initialize/kill pattern with a mandatory re-probe, cache `authMethods`/`authRequired`/`authHint` in `CachedCaps` and project them into `InstanceInfo`/`PreflightReport`, expose `providers_authenticate`, and share one `SignInActions` block between Providers and the onboarding ConnectRow.

**Tech Stack:** Tauri 2 (Rust/Tokio/serde), React 19, TS strict, zustand, Tailwind v4, Vitest, cargo test/clippy.

**Spec:** README.md, DEVLOG.md, TODO.md (account sign-in), protocol/acp-schema.json (`AuthMethod`, `AuthMethodTerminal`, `AuthMethodAgent`, `AuthenticateRequest`).

## Global Constraints

- No SQLite migrations; auth state lives in runtime memory (`CachedCaps`).
- TS strict; IPC errors keep `PultError { code, message }`.
- No new dependencies; no GUI/Playwright/real-CLI runs.
- Never pass a `terminal` method to `authenticate`; never hold `inner.lock()` across `.await`.

## Review Focus

1. A start/protocol error must not be reported as Needs sign-in: only `-32000` means auth required.
2. Terminal methods never reach the `authenticate` RPC.
3. Every error path kills the child process; no lock across await.
4. Cached status/methods survive navigation and `loadInstances()`.
5. A silent `authenticate` success is verified by a second `session/new`; otherwise the UI would claim Connected falsely.

### Task 3: Runtime auth cache, `AgentRuntime::authenticate`, IPC

**Files:** `src-tauri/src/runtime/mod.rs`, `src-tauri/src/ipc/mod.rs`, `src-tauri/src/lib.rs`, `src-tauri/src/runtime/tests.rs`.

**Interfaces:**

- `CachedCaps { auth_methods, auth_required, auth_hint }`; `InstanceInfo` exposes them and maps `auth_required` to status `needs_auth`; `PreflightReport.auth_methods`.
- `AgentRuntime::authenticate(instance_id, method_id) -> PreflightReport`: reject empty/terminal ids, spawn → initialize → authenticate → new_session re-probe → kill on every path; success clears auth state and caches config options/modes; `-32000` keeps Needs sign-in; other errors return `Err`.
- `preflight`: only `is_auth_required` sets Needs sign-in; cache methods; emit `agent:process needs_auth`.
- `resolve_session`: `-32000` caches Needs sign-in and returns `PultError::with_code("auth_required", ...)`; success clears it.
- `PultError::with_code(code, message)`; IPC `providers_authenticate(instance_id, method_id)`.

3. Terminal methods only show command/Re-check.
4. Mock reproduces auth-required, success, failure, terminal.
